# Stitch 国风出图 · 云山竹简（SinoWind）

本 skill 是**出图前的翻译器与出图后的校验器**，不产出业务代码。它把模糊的界面想法变成 Stitch 能一次听懂的结构化提示词，并在生成稿进入代码前拦住破坏国风克制美学与项目红线的设计。

## 唯一真源（先读，再写）

| 文件 | 提供什么 | 优先级 |
| :--- | :--- | :--- |
| `DESIGN.md`（仓库根目录） | 中国传统色谱、意境特征、五大界面元素映射、Stitch 拼合规范 | **最高** |
| `frontend/src/styles/variables.less` | 落地变量的唯一真源（颜色/圆角/边框） | **最高** |
| `TRD_PHASE2.md` §2 | 图标体系红线（禁用生硬图片图标） | 高 |
| `references/DESIGN-TOKENS.md` | 上表两份文件的速查表（色板/字体/组件规格） | 派生 |
| `references/PROMPT-TEMPLATES.md` | 逐屏提示词模板 | 派生 |
| `references/ANTI-PATTERNS.md` | 反模式与项目红线清单 | 派生 |
| `references/CODE-HANDOFF.md` | 生成稿落地到 React 19 + Less 的约定 | 派生 |

**冲突时以 `DESIGN.md` 与 `variables.less` 为准**，本 skill 的速查表只是搬运与翻译。发现代码与 `DESIGN.md` 不一致时（例如底栏栏数），按代码现状出图，并在输出末尾用一行「⚠️ 规范差异」提示，不要静默改写其中一方。

## 何时启用

- 用户要「用 Stitch 做/改某个页面」，或拿着 Stitch 截图回来问「像不像我们项目」。
- 新页面开工前需要一份与现有五屏视觉同源的界面稿。
- 需要把 `DESIGN.md` 里的出图说明变成 Stitch 能吃下的提示词。
- 需要按国风规范校验一份外部生成稿（AI 出图或设计稿）。

不适用：纯后端/接口/数据库改动；已定稿页面的单行文案替换；与界面无关的工程重构。

## 工作流

### 第 1 步 · 判定任务类型

| 类型 | 识别特征 | 提示词策略 |
| :--- | :--- | :--- |
| **新建整屏** | 「做一个 XX 页」 | 完整 `DESIGN SYSTEM` + 分段页面结构 |
| **局部改造** | 「加个搜索框」「气泡改一改」 | 只描述改动点 + 「保留其余元素不变」 |
| **多屏一致** | 一次要好几屏 | 每屏单独一条提示词，共用同一份 `DESIGN SYSTEM` 块 |
| **生成稿校验** | 已有图，要求评价 | 走第 4 步清单，逐条给「符合/违反 + 依据」 |

### 第 2 步 · 组装 DESIGN SYSTEM (REQUIRED) 块

每条提示词都必须自带这段，值从 `references/DESIGN-TOKENS.md` 取，不要凭记忆写色值：

```markdown
**DESIGN SYSTEM (REQUIRED):**
- 平台与画布：移动端竖屏，390 × 844，左右留白 16px（表单页 20px），超出 480px 宽屏居中
- 主题：宣纸水墨、克制典雅、宋代留白美学；禁止科技感与霓虹发光
- 背景：宣纸原色 (#F5F0E6)，带极淡的植物纤维/水墨晕染肌理
- 卡片表面：绢帛玉白 (#FAF7F0)
- 主文字：远山黛墨 (#22252A)；次要文字：淡墨焦墨 (#5C6068)
- 强调色：朱砂印泥红 (#9E2A2B)，仅用于印章、主按钮、激活态
- 辅助色：苍竹墨绿 (#3A5A40)、霁蓝黛青 (#203A4C)、沉香古金 (#C59B27)
- 分隔线：古纸线界 1px solid #E2D9C8（或 1px dashed #D5CAB5）
- 圆角：卡片 10px、按钮 8~12px、印章 4~6px（方正从容，禁用 24px 以上大圆角）
- 字体：标题与诗词用宋体/楷体体系（Songti SC / STKaiti / Noto Serif SC），界面控件与数字用系统无衬线
- 图标：线性矢量图标，1.5px 描边，随文字颜色着色（对应 antd-mobile-icons）
```

### 第 3 步 · 写提示词正文

1. **开头一句话定性**：这个页面是什么、给谁看、什么气质（例：「一位雅士进入自己的书斋查看一年修持成果」）。
2. **分段编号描述结构**：`1. 顶部题头：… 2. 主内容：… 3. 底部：…`。Stitch 对编号层级的还原度明显高于大段散文。
3. **用国风词汇表翻译含糊说法**（见下方对照表），并给出可验证的数值：留白多少、圆角多少、描边几像素。
4. **语言策略**：业务语义与文化意象用中文写（「朱砂篆刻方印」「两端木轴卷轴」），组件与版式术语可补英文关键词（`segmented control`、`bottom tab bar`、`inline seal badge`），提升还原稳定性。
5. **局部改造时一条提示词只改一件事**，并显式声明「仅此一处改动，其余元素、配色、间距保持原样」。
6. **不要搬 `DESIGN.md` 里的出图渲染词**：`8k`、`Figma UI mockup`、`high resolution`、`concept art` 是给绘图模型的，Stitch 需要的是界面结构与组件语义，留着会稀释指令。

### 第 4 步 · 出图前自检

逐条过 `references/ANTI-PATTERNS.md`。高频四问：

- 图标位有没有出现位图剪贴画、原生字符箭头（`>`、`⌄`）或 emoji 冒充图标？
- 有没有出现纯黑 `#000000`、纯白背景、霓虹发光、玻璃拟态？
- 卡片圆角是不是被放大到 24px 以上的「通用 SaaS 圆角」？
- 文案里有没有编造的古诗出处、编造的修持数据（如「99.98% 好评」）？

### 第 5 步 · 输出与落地

- **默认**：把增强后的提示词作为文本返回，供用户直接粘贴进 Stitch。
- **用户要求落文件时**：写入 `next-prompt.md`（便于多轮迭代）或用户指定文件名。
- **生成稿要进代码库时**：按 `references/CODE-HANDOFF.md` 把视觉决策翻译成 Less 变量、`antd-mobile-icons` 组件与路由注册，**不要**把出图稿当作最终实现。
- **随 PR 提交时**：按 `TRD_PHASE2.md` §6.4 附 `docs/handovers/ai-log-<姓名>-<日期>.md`，其中如实登记本 skill 产出的提示词与筛选过程。

## 国风词汇对照表

| 含糊说法 | 翻译成国风精确表达 | 可补的英文关键词 |
| :--- | :--- | :--- |
| 顶部大标题区 | 顶部题头：主标题 + 朱砂篆刻方印 + 一句七言副题 | `header with seal badge` |
| 轮播/横滑卡片 | 两端带木轴的展开式横向卷轴 | `horizontal scroll, roller ends` |
| 主按钮 | 朱砂印章长条按键，象牙白字，微金内边线 | `primary button, no glow` |
| 切换登录/注册 | 朱砂滑块印符「入席 / 缔约」 | `segmented control` |
| 输入框 | 宣纸白内嵌输入位，标签在上、错误在下 | `labeled text field` |
| 列表跳转箭头 | 线性右向箭头图标，朱砂着色 | `chevron icon, currentColor` |
| 卡片 | 竹简式卡片，1px 古纸线界，微纸感投影 | `bordered card, tinted shadow` |
| 数据统计栏 | 雅士修持四维数轴（鉴宝/论道/诗签/品阶） | `stat row` |
| 空状态 | 留白式雅意构图 + 一句引导语，非「暂无数据」 | `empty state, composed` |
| 加载中 | 与版式同尺寸的骨架占位（宣纸灰），不用圆形转圈 | `skeleton, no spinner` |
| 底部导航 | 三栏底栏：雅集 / 观藏 / 书斋，激活项朱砂下划线 | `bottom tab bar` |

## 完整示例

**输入**：「帮我做个个人中心页面，古风一点」

**输出**：

```markdown
一位雅士踏入自己的书斋，查看修持成果与藏品，气质沉静、克制、书卷气。

**DESIGN SYSTEM (REQUIRED):**
- 平台与画布：移动端竖屏，390 × 844，左右留白 16px
- 主题：宣纸水墨、宋代留白；禁止科技感与霓虹发光
- 背景：宣纸原色 (#F5F0E6)；卡片：绢帛玉白 (#FAF7F0)
- 主文字：远山黛墨 (#22252A)；次要文字：淡墨焦墨 (#5C6068)
- 强调色：朱砂印泥红 (#9E2A2B)，仅用于印章、主按钮、激活态
- 辅助色：苍竹墨绿 (#3A5A40)、沉香古金 (#C59B27)
- 分隔线：1px solid #E2D9C8；圆角：卡片 10px、印章 6px
- 字体：标题用楷体/宋体，数字与控件用系统无衬线
- 图标：线性矢量图标，随文字颜色着色

**Page Structure:**
1. **顶部题头**：印章式头像框（朱砂底 40×40、圆角 6px、金线描边）+ 雅号「云山居士」+ 境界徽章「翰林待诏」，题头底为素雅竹林宣纸
2. **修持四维数轴**：一行四项，图标在上、数字在下 —— 鉴宝藏器 / 论道问策 / 诗笺摘录 / 文风品阶，数字取真实计数（无数据时显示占位而非编造）
3. **藏品与墨卷**：两张竹简式卡片，左侧线性图标、右侧标题与右向箭头 —— 琅嬛藏诗阁、博古鉴宝录
4. **书斋清规**：四行设置列表 —— 印信与密押设置、岁时节气提醒、雅集问难答疑、整装离席（退出登录，文字用朱砂）
5. **底部导航**：三栏底栏（雅集 / 观藏 / 书斋），「书斋」为激活态：朱砂图标 + 朱砂下划线

**保留要素**：整屏不使用任何位图图标与 emoji，所有图标位为线性矢量图标。
```

## 常见误区

1. **一次要求太多屏**：Stitch 在多屏混排时会牺牲单屏细节，逐屏出图再统一校验。
2. **只给形容词不给数值**：「高级一点」「古风一点」必须落到色值、圆角、留白、字号。
3. **把 `DESIGN.md` 的出图 Prompt 直接粘给 Stitch**：那是给绘图模型的，需删去渲染词并按上方结构重排。
4. **跳过真源**：凭印象写色值最容易漂移成「泛国风」，务必读 `variables.less`。
5. **把生成稿当交付物**：Stitch 产出的是视觉 intent，进代码前必须过一次 `CODE-HANDOFF.md`。
