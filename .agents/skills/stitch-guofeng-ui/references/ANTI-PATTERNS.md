# 反模式与项目红线

> 出图前逐条自检；生成稿评审时按「违反哪一条 + 依据出处」给出结论。
> 「红线」= 会打回 PR 的硬约束（`TRD_PHASE2.md`），「反模式」= 会破坏国风美学的软约束。

## A. 项目红线（硬约束）

| 编号 | 禁止 | 必须 | 依据 |
| :--- | :--- | :--- | :--- |
| R1 | 随处截取、硬塞格式不一、底色不透、放大模糊的 PNG/JPG 图标 | 使用 `antd-mobile-icons` 官方矢量图标（`RightOutline`/`SearchOutline`/`HeartOutline`/`BookOutline`/`EyeOutline`/`RedoOutline`/`LockOutline`/`SoundOutline` 等） | `TRD_PHASE2.md` §2.1、§2.2 |
| R2 | 用原生字符 `>`、`⌄`、`→` 充当箭头 | 线性箭头矢量图标，随 `currentColor` 着色 | `TRD_PHASE2.md` §2.2；`Home.jsx` 已用 `DownOutline` 替换字符 |
| R3 | 图标无法随激活态换色（死图） | 图标颜色由 CSS 控制，激活态自动变朱砂 `#9E2A2B` | `TRD_PHASE2.md` §2.3 |
| R4 | 色值/圆角/边框在样式里硬编码十六进制 | 引用 `variables.less` 变量（`@color-seal`、`@radius-card` …） | `variables.less` |
| R5 | 编造修持数据、评价分数、用户量等无来源指标 | 展示数据库真实计数；无数据显示占位 | `TRD_PHASE2.md` §3.4 |
| R6 | 私自改动接口返回字段 | 对齐 `docs/PHASE2_API_CONTRACT.md` | `TRD_PHASE2.md` §6.3 |
| R7 | 引用外链图片（`unsplash` 等） | 使用仓库本地素材 `frontend/public/assets/**` | 演示环境弱网/断网兜底要求 |
| R8 | 无 UI 变更却声称使用本 skill 出图 | 保持文档与事实一致 | 本项目提交需附 AI 使用填报表 |

> **例外说明**：底栏三栏图标是设计稿器物切图，以 CSS `mask` + `currentColor` 着色（见 `layout.less`），符合 R3 的着色要求，不属于 R1 的「散装图片图标」。出图稿中底栏图标应表现为**可随激活态变色的线性器物图标**。

## B. 国风特有反模式

| 禁止 | 原因 | 替代 |
| :--- | :--- | :--- |
| 编造不存在的古诗、伪托出处、错置朝代与作者 | 文化类项目的可信度红线，评审一眼可见 | 只用真实名篇；不确定就不写，或标注待核对 |
| 简繁混排、异体字混用（如「雲山竹简」与「云山」同屏） | 显得随意、不专业 | 全站简体（`DESIGN.md` 中「華風」印章为篆刻意象，属设计元素，正文一律简体） |
| 伪文言文案腔（「探索无限可能 · 启幕雅集新纪元」） | 与宋代克制美学相悖，是 AI 腔 | 用具体、朴素的短语：「读千年风雅」「焚香点茶筹备中，静候雅聚」 |
| 印章滥用（每张卡片都盖印、印章做按钮背景重复铺满） | 印章是品牌锚点，过度使用即失效 | 一枚印章只出现在：Logo、主按钮、句末落款、境界徽章 |
| 纹样堆砌（回纹 + 云纹 + 缠枝纹 + 描金同时出现） | 装饰压过内容，廉价感 | 一个区域至多一处装饰元素（回纹角或描金线，二选一） |
| 大字号书法体做长正文 | 可读性崩塌 | 书法/楷体只用于标题、诗句、雅号；正文用系统无衬线 |
| 玻璃拟态、毛玻璃、霓虹外发光、AI 紫蓝渐变 | 科技感与宣纸水墨体质冲突 | 纸感微投影（`fade(#3a2f1d, 7%)` 级别）+ 描边 |
| 24px 以上大圆角、胶囊化滥用 | 古风以方正从容为贵 | 卡片 10px、印章 6px |
| 现代社交蓝底聊天气泡 | 与霁蓝黛青体系冲突 | 宣纸白（用户）/ 霁蓝黛青 `#203A4C`（先贤） |
| 圆形转圈加载 | 与留白美学冲突 | 与版式同尺寸的宣纸灰骨架占位 |
| 「暂无数据」干文案空态 | 破坏雅意 | 留白式构图 + 一句引导语 |
| 无标题层级的大段居中文字 | 排版失控 | 编号分段结构 + 明确对齐方式 |

## C. 通用 AI 设计痕迹（出图自检四问）

1. 有没有出现纯黑 `#000000` 或纯白 `#FFFFFF` 的整屏背景？（应为 `#F5F0E6` / `#FAF7F0`）
2. 强调色是否只有一个？（出现第二种高饱和强调色即违反）
3. 有没有「三张等宽卡片横排」的通用功能行？（本项目用 2×2 宫格或横向卷轴）
4. 文案里有没有 `Elevate`/「赋能」/「一站式」/「极致体验」这类空洞词？

## D. emoji 的边界

项目中 emoji 仅作为**文案点缀**存在（如 `DESIGN.md` 的风物标签 🍵📜👘🌸🎋），**不得**出现在任何图标位、按钮位、导航位。图标位只能用 `antd-mobile-icons`（R1）。

## E. 自检输出格式

评审生成稿时按此格式给结论，避免「感觉不太像」这类无法执行的反馈：

```markdown
| 检查项 | 结论 | 依据 |
| :--- | :--- | :--- |
| 图标位 | ✅ 通过 / ❌ 违反 R1 | 说明具体位置 |
| 色板 | ✅ / ❌ | 指出偏色值 |
| 圆角与描边 | ✅ / ❌ | 指出实测值 |
| 文案与文化准确性 | ✅ / ❌ | 指出编造或错置处 |
| 建议改法 | — | 给出可直接投喂 Stitch 的修正句 |
```
